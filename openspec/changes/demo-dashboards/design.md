## Tech Stack
- HTML5/CSS3/JavaScript для интерфейса дашборда
- Chart.js для построения линейных графиков, столбцовых диаграм и воронок конверсии
- d3.js для дополнительных визуализаций и сложных взаимодействий
- Bootstrap 5 для базовой стилизации и отзывчивого дизайна
- ES6+ модули для организации кода

## Architecture
- **Single Page Application (SPA)**: один HTML-файл с динамической загрузкой контента
- **Modular structure**: разделение на независимые модули (KPI, funnel, dynamics, comparison, insights, export)
- **Data-driven approach**: все компоненты получают данные через единый JSON-формат, не зависят от конкретного источника
- **Separation of concerns**: HTML-структура, CSS-стили, JS-логика разделены в отдельных файлах, но загружаются как единое приложение

## Data Structure
- **Input format**: JSON массив объектов вызовов с полями:
  - `callId` (уникальный идентификатор)
  - `timestamp` (время звонка, ISO format)
  - `duration` (длительность в секундах)
  - `stage` (этап воронки: 'greeting', 'offer', 'proposal', 'agreement')
  - `result`: 'dropped_before_dialogue', 'dropped_during_dialogue', 'completed', 'meeting_scheduled'
  - `hour` (час суток 0-23)
  - `dayOfWeek` (0-6, пн-вс)
- **Data delivery**: статический JSON-файл или через REST endpoint возвращающий агрегированные метрики
- **Pre-aggregated data**: KPI-суммы рассчитываются на стороне бэкенда или при загрузке дашборда

## Key Components
1. **KPIModule** - карточки с основными метриками: общее число звонков, с диалогом/без диалога, завершения бота, конверсия во встречу, недельная динамика
2. **FunnelModule** - визуализация воронки конверсии с пошаговым прохождением (Приветствие -> Оффер -> Предложение встречи -> Согласие), расчет процентов и потерь на каждом этапе
3. **DynamicsModule** - графики динамики: звонки по дням недели, по часам суток, распределение длительности разговора
4. **ComparisonModule** - сравнение метрик текущего периода с предыдущим (неделя/месяц) по всем KPI и конверсиям
5. **InsightsModule** - автоматический вывод ключевых находок и рекомендаций на основеpatterns оттока клиентов
6. **ExportModule** - экспорт текущего вида данных в CSV формат

## Dependencies
- Chart.js v4.4.0 (стандартные графики: bar, line, doughnut)
- d3.v7.min.js (дополнительные визуализации, оси, анимации)
- Bootstrap 5.3.3 (стили и грид-система)
- Font Awesome 6.4.0 (иконки для интерфейса)
- Eslint для проверки кода (опционально)
- No external backend dependencies - дашборд работает с фиксированным набором данных

## Non-Functional Requirements
- **Performance**: поддержка до 10,000 звонков без лагов, оптимизированная отрисовка графиков
- **First Contentful Paint**: время первой отрисовки < 2 секунд при загрузке с кэша
- **Browser Support**: Chrome, Firefox, Edge (последние 2 версии), Safari 15+
- **Responsive Design**: desktop (1920x1080), tablet (768x1024), mobile (375x667) - адаптивная воронка и KPI-карточки

## Error Handling
- **JSON load failure**: показать сообщение "Данные недоступны, попробуйте обновить страницу" и скрыть графики
- **Invalid data**: автоматическая фильтрация ошибочных записей, показ количества пропущенных записей в консоли
- **CDN fallback**: если Chart.js не загрузился с CDN, использовать локальный fallback-файл или отключить графические элементы с сообщением о деградации функционала

## Testing Strategy
- **Unit tests**: для расчёта KPI-метрик, фильтрации данных, расчёта конверсии на каждом этапе воронки
- **E2E tests**: для критических сценариев из spec-файлов: загрузка данных, обновление KPI, корректность воронки, экспорт CSV, переключение периодов
- **Visual regression**: базовые проверки отображения графиков на разных разрешениях

## Build & Deployment
- **Bundler**: Vite для сборки ES-модулей, производительная сборка с минификацией
- **Deployment**: статические файлы (HTML/CSS/JS) деплоятся на любой веб-сервер (Nginx, S3, Vercel)
- **Versioning**: файл версии в main.js, возможность безошибочного обновления без перезагрузки страницы

## State Management
- **Data flow**: главный модуль инициализации загружает JSON-данные и передает их дочерним модулям через функции рендеринга
- **Global state**: минимальное использование глобального состояния, каждый модуль получает данные пропсами или через вызов init(data)
- **Cache**: опциональное сохранение последних данных в localStorage для быстрого восстановления при перезагрузке

## Data Caching
- **localStorage**: сохранять агрегированные KPI-метрики на 24 часа для ускорения повторных визитов
- **Data refresh**: при обновлении страницы новые данные загружаются из источника, если они есть
- **Cache invalidation**: при изменении периода сравнения кэш очищается автоматически
